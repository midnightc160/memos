# Memos 认证鉴权和用户隔离分析

## 一、认证机制 (Authentication)

### 1.1 三种认证方式

**1. JWT Access Token (短期令牌)**
- 有效期：15分钟
- 用途：API访问的主要认证方式
- 验证：无状态，仅通过签名验证
- 包含信息：用户ID、用户名、角色、状态

**2. JWT Refresh Token (长期令牌)**
- 有效期：30天
- 用途：获取新的Access Token
- 验证：需要数据库查询验证是否被撤销
- 存储：HttpOnly Cookie，支持令牌轮换

**3. Personal Access Token (PAT)**
- 前缀：`memos_pat_`
- 用途：程序化访问
- 验证：通过SHA-256哈希值在数据库中验证
- 特点：长期有效，可设置过期时间

### 1.2 认证流程

**登录流程：**
```
用户提交凭证 → 验证密码/SSO → 生成Token对 → 设置Cookie → 返回Access Token
```

**API访问流程：**
```
请求携带Token → 拦截器验证 → 提取用户信息 → 设置Context → 业务逻辑
```

**Token刷新流程：**
```
Refresh Token → 验证有效性 → 生成新Token对 → 撤销旧Token → 返回新Access Token
```

## 二、鉴权机制 (Authorization)

### 2.1 用户角色系统

**角色定义：**
- `ADMIN`: 管理员 - 全站管理权限
- `USER`: 普通用户 - 个人数据管理权限

**权限控制点：**
- API层面：通过用户角色控制功能访问
- 数据层面：通过CreatorID控制数据所有权
- 实例层面：通过实例设置控制全局行为

### 2.2 数据可见性系统

**Memo可见性级别：**
```go
type Visibility string

const (
    Public     Visibility = "PUBLIC"     // 所有人可见
    Protected  Visibility = "PROTECTED"  // 登录用户可见
    Private    Visibility = "PRIVATE"    // 仅创建者可见
)
```

**访问控制逻辑：**
1. 未登录用户：只能看到PUBLIC memos
2. 登录用户：可以看到自己的所有memos + 其他人的PUBLIC/PROTECTED memos
3. 创建者：对自己的memo有完全控制权

## 三、用户隔离机制

### 3.1 数据隔离

**核心隔离字段：**
```go
type Memo struct {
    CreatorID  int32     // 创建者ID - 核心隔离字段
    Visibility Visibility // 可见性控制
}
```

**数据库层面隔离：**
- 所有用户数据都有CreatorID字段
- 查询时自动添加用户过滤条件
- 更新/删除操作验证所有权

**API层面隔离：**
```go
// 示例：ListMemos中的用户隔离逻辑
if currentUser == nil {
    // 未登录：只看PUBLIC
    memoFind.VisibilityList = []store.Visibility{store.Public}
} else {
    if memoFind.CreatorID == nil {
        // 已登录且未指定创建者：看自己的+他人的PUBLIC/PROTECTED
        filter := fmt.Sprintf(`creator_id == %d || visibility in ["PUBLIC", "PROTECTED"]`, currentUser.ID)
    } else if *memoFind.CreatorID != currentUser.ID {
        // 查看他人数据：只能看PUBLIC/PROTECTED
        memoFind.VisibilityList = []store.Visibility{store.Public, store.Protected}
    }
}
```

### 3.2 会话隔离

**Refresh Token管理：**
- 每个用户的refresh token独立存储在user_setting中
- 支持多设备登录（每个设备一个token）
- 登出时撤销特定token，不影响其他设备

**设备识别：**
```go
type ClientInfo struct {
    UserAgent   string  // 用户代理
    IpAddress   string  // IP地址
    DeviceType  string  // 设备类型：mobile/tablet/desktop
    Os          string  // 操作系统
    Browser     string  // 浏览器
}
```

## 四、安全特性

### 4.1 Token安全

**Access Token：**
- 短期有效（15分钟）降低泄露风险
- 无状态验证提高性能
- 包含签名防止篡改

**Refresh Token：**
- HttpOnly Cookie防止XSS
- 令牌轮换防止重放攻击
- 数据库存储支持即时撤销

**PAT Token：**
- SHA-256哈希存储，原始token不保存
- 支持过期时间设置
- 记录使用时间便于审计

### 4.2 会话安全

**Cookie设置：**
- HttpOnly：防止JavaScript访问
- SameSite=Lax：防止CSRF攻击
- Secure（HTTPS环境）：防止中间人攻击

**防护措施：**
- 密码BCrypt加密存储
- JWT使用HMAC-SHA256签名
- 支持账户禁用（RowStatus=ARCHIVED）

### 4.3 实例级安全控制

**全局设置：**
- `DisallowPasswordAuth`：禁用密码登录
- `DisallowUserRegistration`：禁用用户注册
- `DisallowPublicVisibility`：禁用公开memo

## 五、总结

Memos的认证鉴权系统设计完善：

✅ **多层认证**：支持JWT双token + PAT三种认证方式
✅ **严格隔离**：基于CreatorID的数据所有权 + Visibility的访问控制
✅ **安全第一**：短期token + 令牌轮换 + HttpOnly Cookie
✅ **灵活授权**：角色系统 + 可见性控制 + 实例级配置
✅ **审计能力**：设备识别 + 使用记录 + 会话管理

这套机制确保了多用户环境下的数据安全和隐私保护。
